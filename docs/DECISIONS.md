## 2026-07-15 — UI 다국어: 클라이언트 사전 방식 (이슈 #8)

**결정**: UI 문구도 한/영/일로 번역한다(기존 "UI 문구는 한국어" 컨벤션을 확장). 방식은 **클라이언트 사전** — `src/lib/i18n.ts`에 한국어를 소스로 두고 `en`/`ja`를 같은 키로 강제하는 사전을 두며, 컴포넌트는 `useT()`의 `t("key", vars?)`로 현재 언어(`useLanguage`)에 맞는 문구를 뽑는다. `{name}` 자리표시자는 `interpolate`로 채운다. 정적 export(GitHub Pages) 구조는 그대로 두고, 첫 렌더는 한국어(프리렌더 HTML)와 일치시킨 뒤 하이드레이션 후 전환한다.

- 서버 컴포넌트의 가시 문구(헤더 브랜드/푸터/페이지 제목·부제)는 작은 클라이언트 컴포넌트(`SiteChrome`, `PageHeader`)로 추출해 번역한다.
- 순수 로직이 라벨 문자열을 반환하던 곳(`koVerdict`)은 언어 중립적 `kind`를 반환하도록 바꾸고, 문구 포맷은 컴포넌트에서 `t()`로 한다.
- **범위(1차)**: 계산기 2종(`/damage`, `/speed`)과 공용 헤더/푸터·페이지 헤더. **후속**: 홈·도감 등 정적 페이지 문구, SEO 메타데이터(현재 한국어 유지 — 정적 HTML), 아이템 이름 등 데이터성 라벨(`battleModifiers`의 `ItemOption`에 `en`/`ja` 추가 필요).

**이유**: 앱이 정적 export + 클라이언트 언어 토글(데이터 이름만 번역) 구조라, 로케일 라우팅(`/en`, `/ja`)보다 사전 방식이 기존 구조를 건드리지 않고 토글 즉시 반영되어 위험이 적다. 트레이드오프로 SEO 메타데이터는 언어별로 분기되지 않는데, 1차 범위에서는 허용한다. 향후 언어별 검색 유입이 중요해지면 로케일 라우팅을 별도 결정으로 재검토한다.

## 2026-07-10 — 챔피언스 스피드/노력치 공식 (Lv50)

**결정**: Lv50 능력치 계산에서 챔피언스의 노력치(EV)는 0~32 스케일이며, **성격 적용 전 능력치 = 종족값 + 20 + EV**로 계산한다. 최종 = `floor((종족값 + 20 + EV) × 성격보정)`, 성격보정 = +1.1 / 무보정 1.0 / -0.9. (개체값은 31 고정 가정. HP는 별도이나 스피드 계산엔 불필요.) 구현: `src/lib/speed.ts`.

**이유**: championsbattledata의 무보정·0EV Lv50 실능력치가 `종족값 + 20`(비HP, 31개체값)과 일치함을 이미 검증했고, 전통 공식에서 Lv50의 노력치 최대 투자 시 성격 전 보너스가 정확히 +32다(종족값+20 → +52). 따라서 챔피언스의 0~32 EV는 성격 전 능력치에 그대로 선형으로 더해진다. 교차검증: 한카리아스(종족값 102) 무보정 0EV=122·최속 169, 드래펄트(142) 최속 213 — 전통 계산과 일치. 데미지 계산기에서도 같은 공식을 재사용한다.

## 2026-07-09 — 에셋: 비영리·면책 조건으로 사용

**결정**: 포켓몬 타입 아이콘·스프라이트 등 공식 에셋을 **비공식 팬 프로젝트** 전제로 사용한다. 구체적으로:

- **타입 아이콘**(`public/types/*.png`, 18종)은 저장소에 커밋해 로컬 정적 파일로 사용.
- **포켓몬 스프라이트**는 championsbattledata에서 핫링크(저장소 재배포 없음).
- 모든 페이지 하단에 **면책 문구**(닌텐도·게임프리크·포켓몬 컴퍼니와 무관, 저작권은 각 권리자) 상시 노출.

**이유**: 공식 에셋은 저작권상 회색지대지만, Serebii·Bulbapedia·Smogon·Pikalytics 등 대형 팬 사이트가 관행적으로 사용하며 비영리 규모에서 제재 사례는 드물다. 타입 아이콘은 특히 리스크가 낮다. 면책 문구로 "공식 사칭"을 방지한다.

**단, 수익화 시 재검토**: 광고·유료화 같은 상업적 이용은 닌텐도 가이드라인상 비허가이며 회색지대에서 벗어난다(특히 데이터마이닝 소스 사용). 수익화가 필요하면 Pikalytics식 도네이션이 광고보다 안전하고, 진지한 상업화 전에는 정식 법률 검토를 둔다.

## 2026-07-08 — 데이터 소스: 스냅샷 JSON 소유 (B안)

**결정**: 외부 API를 런타임에 직접 호출하지 않고, 기존 소스에서 받아 정제한 뒤 **우리 저장소에 스냅샷(정적 JSON/상수)으로 소유**한다.

- **소스 역할 분담**
  - `PokéAPI` (pokeapi.co) — 본가 기준 불변 데이터(타입 상성, 도감 설명, 스프라이트, 정통 종족값). 안정적이나 챔피언스 고유값·최신 메타는 없음(전국도감 1025까지 커버, 갱신은 자원봉사 기반이라 지연).
  - `championsbattledata.com` — 챔피언스 전용 데이터(로스터 235종, 챔피언스 스탯/타입/특성, 사용률 통계). 단, 개인 팬이 운영하는 **집계층**이라 불안정.
- **원천 제작(A안)은 채택하지 않음**: 게임 데이터마이닝·인게임 사용률 직접 집계는 팬 사이트가 이미 하는 일을 재현하는 것이라 비효율. 우리는 "원천 제작"이 아니라 "정제 후 소유"만 한다.
- **데이터를 변동성 3등급으로 나눠 다르게 취급**
  - 불변(타입 상성표 18×18) → 코드 상수로 하드코딩(`src/lib/typeChart.ts`), fetch 불필요.
  - 느림(로스터·종족값·학습기) → 스냅샷 JSON. 게임 패치 때만 갱신.
  - 빠름(사용률·메타) → MVP에서는 보류. 다룰 경우 시즌 단위로 스냅샷 재생성.
- **구현 형태**: `scripts/`에 인제스트 스크립트를 두어 위 소스에서 받아 정규화 → `src/lib/data/*.json`으로 커밋. 런타임/빌드는 이 로컬 데이터만 읽는다.

**이유**: 포켓몬 챔피언스는 **공식 공개 API가 존재하지 않는다**(더 포켓몬 컴퍼니는 게임 데이터 API를 제공한 적 없음). 선택지가 전부 비공식이므로 어떤 소스든 끊길 수 있다. 이 서비스는 SSG(정적 페이지)와 북마크형 계산기라 데이터가 빌드 타임에 로컬에 있는 편이 유리하고, 대상 데이터가 거의 불변이라 런타임 API 의존의 이점이 없다. 스냅샷 소유는 팬 API 중단에도 사이트가 계속 동작하게 하고, 버전 관리·재현성·리뷰 가능성을 확보한다.

## 2026-07-08 — Next.js 채택 (Vite SPA 대신)

**결정**: 프레임워크로 Next.js 16 (App Router) 사용.

**이유**: 이 서비스는 "북마크해서 쓰는 계산기"이면서 동시에 검색 유입도 원한다.
유입은 검색(포켓몬별 정적 페이지, SSG), 재방문은 북마크(클라이언트 계산기)로 일어나므로
정적 생성과 SPA 경험을 한 프로젝트에서 해결할 수 있는 Next.js가 적합.
순수 도구였다면 Vite + React SPA로 충분했다.

## 2026-07-08 — 상태 관리: Zustand + TanStack Query 분리

**결정**: 서버 데이터(포켓몬 정보 등)는 TanStack Query, 클라이언트 상태(팀 구성, 계산기 입력)는 Zustand.

**이유**: 포켓몬 데이터는 거의 불변이라 Query 캐싱(staleTime 1시간)에 잘 맞고,
팀 구성 같은 UI 상태는 Zustand가 Redux 대비 보일러플레이트가 적다.

## 2026-07-08 — 스탯은 정통 종족값으로 저장 (Lv50 수치 역산)

**결정**: 스냅샷의 `baseStats`에는 **정통 종족값**(예: Garchomp HP 108)을 저장한다. championsbattledata가 주는 Lv50/31개체값/0노력치/무보정 실능력치를 인제스트에서 역산해 종족값으로 복원한다: HP `종족값 = 값 - 75`, 나머지 `값 - 20`. UI(도감)에는 **종족값 총합(BST)** 을 표시한다.

**이유**: 처음엔 Lv50 실수치를 그대로 저장했으나, (1) 실수치 총합은 표준 지표가 아니라 사용자에게 의미가 약하고, (2) 데미지 계산기는 개체값·노력치·성격·레벨을 사용자가 조정하므로 결국 종족값이 있어야 한다. 31개체값에서는 역산 공식의 버림항이 상쇄되어 **정확히** 복원된다(손실 없음). PokéAPI `base_stat_total`과 교차검증 완료: Abomasnow 494, Garchomp 600, 알로라 나인테일 505, 로토무(히트) 520 등 전부 일치. 별도 PokéAPI 종족값 페치가 불필요해져 소스도 단순해졌다.
