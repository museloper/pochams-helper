## 2026-07-08 — Next.js 채택 (Vite SPA 대신)

**결정**: 프레임워크로 Next.js 16 (App Router) 사용.

**이유**: 이 서비스는 "북마크해서 쓰는 계산기"이면서 동시에 검색 유입도 원한다.
유입은 검색(포켓몬별 정적 페이지, SSG), 재방문은 북마크(클라이언트 계산기)로 일어나므로
정적 생성과 SPA 경험을 한 프로젝트에서 해결할 수 있는 Next.js가 적합.
순수 도구였다면 Vite + React SPA로 충분했다.

## 2026-07-08 — 상태 관리: Zustand + TanStack Query 분리

**결정**: 서버 데이터(포켓몬 정보 등)는 TanStack Query, 클라이언트 상태(팀 구성, 계산기 입력)는 Zustand.

**이유**: 포켓몬 데이터는 거의 불변이라 Query 캐싱(staleTime 1시간)에 잘 맞고,
팀 구성 같은 UI 상태는 Zustand가 Redux 대비 보일러플레이트가 적다.
